01站点是怎么工作的

这是一个 纯静态站点：所有页面是 HTML + JS，内容以 JSON 数据驱动，托管在 GitHub Pages 上。新闻内容不是人工编辑的，而是由 DimAgent 的 ai-news-daily workflow 每天自动抓取、清洗、生成。

  1. Workflow 抓取：ai-news-daily 并行搜索 4 个方向（模型发布 / 前沿研究 / 融资动态 / 政策监管），每个方向由子 agent 用 WebSearch + WebFetch 收集新闻
  2. 清洗输出 JSON：去重、排序、打分类标签，写入 data/YYYY-MM-DD.json
  3. 静态页渲染：index.html（首页列表）和 report.html（日报）读取 JSON 动态渲染
  4. 发布：./update.sh 重建清单、git 提交并推送到 GitHub
  5. 上线：GitHub Pages 检测到 main 分支更新，自动构建，几分钟内生效

02Workflow：ai-news-daily

Workflow 是 DimAgent 里可复用的自动化流程脚本（.mjs），保存在仓库 .dim/workflows/ai-news-daily.mjs，并同步到 DimAgent 的注册目录 ~/.dimcode/v2/data/workflows/saved/，每次新会话启动时自动注册。

整个流程分三个阶段：

  1. 搜索新闻：主流程用 api.parallel 并行启动 4 个子 agent，每个负责一个方向，通过 WebSearch 搜索最近一周的 AI 新闻，并用 WebFetch 抓取原文提取中文摘要，按 schema 返回结构化 JSON
  2. 合并粗去重：主流程把 4 组结果合并，按标题做初步去重
  3. 清洗写入：最后一个子 agent 做语义去重、按重要性排序、校验字段，用 write 工具把严格 JSON 写入 data/YYYY-MM-DD.json

03定时任务：launchd

Workflow 依赖 DimAgent 运行，无法放进 GitHub Actions，所以定时任务跑在本机：macOS 的 launchd 每天 09:00 自动触发。

  1. plist 配置：~/Library/LaunchAgents/com.dimcode.ai-news-daily.plist（StartCalendarInterval 每天 09:00）
  2. 触发脚本：.dim/workflows/run-ai-news-daily.sh（同步在 saved 目录），脚本 cd 到仓库后，用 dim exec 无头模式运行 workflow，数据直接写入仓库 data/ 目录 —— 这就是 workflow 与仓库的绑定
  3. 运行日志：output/ai-news-daily.log（仓库内，git 忽略）
# 查看运行日志
tail -f output/ai-news-daily.log

# 手动触发一次（等价于定时任务）
.dim/workflows/run-ai-news-daily.sh

04GitHub Pages

站点从 main 分支根目录发布（legacy 构建模式）。每次 push 到 main，GitHub 会自动重新构建，无需手动部署。

# 首次开启 GitHub Pages（gh CLI 方式）
gh api --method POST repos/liushengxian/ai-news/pages \
  -f "source[branch]=main" -f "source[path]=/"

# 查看发布状态（building → built）
gh api repos/liushengxian/ai-news/pages --jq '.status'

05每日发布流程

定时任务只负责生成数据（写入 data/），发布需要单独执行 ./update.sh（也可以把两件事串成一条 cron/launchd 命令）。

# 1. 运行 workflow —— launchd 每天 09:00 自动完成
#    或手动：在 DimAgent 会话中运行 ai-news-daily
#    （数据写入 data/2026-08-04.json）

# 2. 发布
./update.sh
✓ 清单更新: reports.json (N 期)
✓ 已提交
✓ 已推送 GitHub Pages，几分钟内生效

# 3. 等待 1-2 分钟后访问
open https://liushengxian.github.io/ai-news/

update.sh 做了三件事：从 data/*.json 扫描重建 reports.json 清单 → git 提交（含数据与脚本变更）→ 推送到 main。首页列表是读取清单动态渲染的，所以新一期出现不需要改任何页面代码。

06日常维护

  1. 修改 workflow：改 .dim/workflows/ai-news-daily.mjs 后，同步到注册目录：cp .dim/workflows/ai-news-daily.mjs ~/.dimcode/v2/data/workflows/saved/
  2. 修改定时脚本：同理同步 run-ai-news-daily.sh；改完无需重载 plist（launchd 每次触发时重新读取脚本）
  3. 补跑漏发的一天：运行 workflow 后用 ./update.sh 发布，数据文件和清单按日期独立，互不影响
  4. 备份与迁移：整个站点就是仓库本身；在新机器上 clone 仓库 + 安装 DimAgent + 同步 saved 目录 + 配置 plist 即可复刻
